# Flowlog Play 스토어 출시 체크리스트

Play 스토어 출시를 앞두고 **결정한 것**과 **남은 할 일**을 한곳에 둔다. 결정은 저장소 주인이 했고, 조사·정리는 2026-10-20 점검 세션이 했다. 보안 점검의 구체 내용은 공개 저장소에 두지 않으므로 여기에는 항목 이름만 적는다. 항목이 끝나면 체크하고, 결정이 바뀌면 이 파일을 고친다(시간순 기록이 아니라 현재 기준).

## 결정 (2026-10-20)

- **결제 모델**: 평소에는 무료 앱. 기록, 오늘·최근 통계, 내보내기는 계속 무료. **서버에 저장(동기화)하고 웹 대시보드(PC)에서 보려면 구독.** 명분은 서버 유지 비용. 가격은 월 1,000원대. 상세 통계 화면(예: 경기 기록 사이트처럼 자세한 정리)이나 AI 연결은 구독 명분의 후보로 두되 아직 정하지 않았다.
- **미리 알리기**: 출시 때부터 앱과 스토어 설명에 "동기화·웹은 베타 기간 무료, 이후 구독으로 전환 예정"을 적는다. 베타 사용자의 처우(평생 무료로 둘지)는 미정.
- **하지 않는 것**: 광고, 일회 구매로 평생 동기화 약속.
- **디자인**: 현재 방향을 유지한다. 다크 모드는 디자인 철학에 속하므로 주인이 직접 손본다.

## 정책 때문에 못 넘어가는 것

- [ ] **비공개 테스트: 12명이 14일 연속.** 신규 개인 개발자 계정은 Play Console의 비공개 테스트 트랙에 테스터 12명 이상이 14일 연속으로 참여한 뒤에야 프로덕션(정식 출시) 신청이 열린다. 테스터는 초대만으로는 안 세고 실제로 참여(opt-in)해야 하며, 중간에 빠지면 14일이 다시 시작된다. 14일이 걸리므로 가장 먼저 시작한다. 주변에 테스터가 부족하면: 기존 사용자와 가족 계정 + 개발자끼리 서로 테스트해 주는 커뮤니티(레딧 r/AndroidClosedTesting 류, 한국어로는 "비공개 테스트 품앗이"로 검색). 돈 주고 사는 테스터 서비스와 본인 계정 여러 개는 쓰지 않는다 — 프로덕션 신청 때 Google이 테스트 내용과 피드백을 묻고, 가짜로 보이면 거절하거나 계정을 제재할 수 있다. 테스터 피드백은 메모해 둔다(신청서에 적는다).
- [ ] **계정 삭제 경로 (유보 14일).** Google 로그인(계정 생성)이 있으므로 앱 안에서 계정과 데이터를 삭제하는 길, 웹에서 삭제를 요청하는 링크, 그리고 데이터 안전 양식에 그 링크를 적는 것 세 가지가 모두 필요하다. 결정(2026-10-20): 삭제를 누르면 서버에 "삭제 예약 + 요청 날짜"를 적고 폰 데이터를 지운 뒤 로그아웃한다. **14일 안에 다시 로그인하면 예약을 취소**하고 서버 기록을 복원한다(앱을 못 쓰는 사람은 문의하면 주인이 예약을 푼다). 14일이 지나면 **예약 작업(Cloud Function, 요금제는 이미 Blaze)**이 서버 기록과 로그인 계정을 영구 삭제한다. 규칙이 삭제를 막는 컬렉션은 내용만 비운다. 유보 기간은 처리방침에 적는다. 지금 앱에는 계정 삭제·전체 삭제가 없다. 평소에 기록 하나를 지울 때 서버에 내용째 남는 방식(tombstone)도 같이 손본다(표시와 식별자만 남김).
- [ ] **데이터 안전 양식과 개인정보 처리방침 정합.** Crashlytics·Firestore 수집 항목, 관리자 열람 여부, 삭제·보존 방식을 처리방침(/privacy/)과 양식에 맞게 적는다.
- [x] 앱 쪽 완료(2026-10-20): 정확 알람 권한을 설명 후 한 번만 묻고, 설정 창에서 다시 켤 수 있으며, 권한이 켜지면 알람을 다시 잡는다. 남은 것: [ ] Play Console에 정확 알람 용도 신고.
- [x] 온보딩의 "Flowlog AI" 문구 제거(2026-10-20). 제안 창 아이콘의 낭독 이름 "AI 메신저"는 기능 이름이라 남김.

## 출시 전 안전·운영

- [ ] **Firestore 규칙 검증 보강**(로그인 요구, 필드·길이·개수 제한), **App Check**, **Firebase 예산 알림**. 세부는 비공개 점검 보고서.
- [ ] **서명 키 백업(PC 밖)과 Play 앱 서명 등록.** 키를 잃으면 같은 패키지로 업데이트를 못 올린다.
- [ ] **스토어 자료**: 스크린샷, 설명, 처리방침 URL. 설명·처리방침 문구·데이터 안전 양식 답안 초안은 `STORE_RELEASE_DRAFTS.md`. 네임스페이스 `com.example`는 Play와 무관(applicationId는 `org.pfkfks.flowlog`).
- [x] 로그 정리(2026-10-20): 제목·uid가 찍히던 로그 19줄을 id·개수로 바꿈.
- [ ] **백업 규칙 결정**: 자동 백업에 무엇을 넣을지(로그인 정보 제외 여부).

## 구독 구현 (베타 뒤)

- [ ] Play Billing 구독 상품 1개(월, 1,000원대). 연간 옵션은 검토.
- [ ] 구독 상태로 동기화·웹 접근을 여닫는 장치(서버 규칙 또는 사용자 클레임). 로컬 기능은 영향 없음.
- [ ] 무료 베타 종료 안내 흐름과 베타 사용자 처우 결정.
- [ ] **무료 사용자의 기기 이전 경로 = 파일.** 서버 복원은 구독에만 둔다(폰 바꿀 때만 잠깐 구독하는 사용을 편하게 만들어 줄 이유는 없다). 대신 내보내기(이미 있음)에 **JSON 가져오기**를 붙여 무료 사용자도 파일로 옮길 수 있게 한다. 구독을 해지한 사용자의 서버 데이터 보존 기간과 삭제 시점은 처리방침에 적는다.

## 디자인 (주인이 직접)

- [ ] **다크 모드.** 현재 화면이 흰색을 직접 칠해 시스템 다크 모드에서 사실상 라이트 전용이다. 주인이 직접 손본다. 그 전까지는 라이트로 고정하는 것이 가장 안전한 선택지다.
- [ ] 접근성 작은 손질(아이콘 설명, 터치 목표 48dp), 한·영 혼재 문구 정리.
- 2026-10-20 점검 세션의 시안 두 개(Calm, River)는 참고 자료로만 둔다.
