# Flowlog Play 스토어 출시 현황

Play 스토어 출시를 앞두고 **결정한 것**과 **항목별 현재 상태**를 한곳에 둔다. 결정은 저장소 주인이 했고, 조사·정리는 2026-10-20 점검 세션, 상태 갱신은 2026-10-21 세션이 했다. 보안 점검의 구체 내용과 비용·콘솔 세부는 공개 저장소에 두지 않고 웹 저장소(비공개) `docs/flowlog-release-plan.md`에 둔다. 상태가 바뀌면 이 파일을 고친다(시간순 기록이 아니라 현재 기준).

상태 표기: **완료** / **일부** (끝난 부분과 남은 부분을 같이 적음) / **보류** (주인이 미룸, 이유 적음) / **남음** (아직 손대지 않음).

## 결정 (2026-10-20)

- **결제 모델**: 평소에는 무료 앱. 기록, 오늘·최근 통계, 내보내기는 계속 무료. **서버에 저장(동기화)하고 웹 대시보드(PC)에서 보려면 구독.** 명분은 서버 유지 비용. 가격은 월 1,000원대. 상세 통계 화면(예: 경기 기록 사이트처럼 자세한 정리)이나 AI 연결은 구독 명분의 후보로 두되 아직 정하지 않았다.
- **미리 알리기**: 출시 때부터 앱과 스토어 설명에 "동기화·웹은 베타 기간 무료, 이후 구독으로 전환 예정"을 적는다. 베타 사용자의 처우(평생 무료로 둘지)는 미정.
- **하지 않는 것**: 광고, 일회 구매로 평생 동기화 약속.
- **디자인**: 현재 방향을 유지한다. 다크 모드는 디자인 철학에 속하므로 주인이 직접 손본다.
- **무료 사용자의 기기 이전 경로 = 파일.** 서버 복원은 구독에만 둔다. 무료 사용자는 내보내기 + JSON 가져오기로 옮긴다.

## 현재 상태 (2026-10-21)

### 콘솔·운영 (주인만 할 수 있는 것)

| 항목 | 상태 | 내용 |
|---|---|---|
| 웹 백엔드 배포 (인덱스·규칙·함수) | **완료** | 2026-10-21 웹 저장소의 백엔드 배포 워크플로가 끝까지 성공했다. 배포 서비스 계정에 편집자·서비스 계정 사용자·Cloud Run 관리자 역할을 주고, 프로젝트에 Cloud Billing API를 켰다. 인덱스(루틴 화면·요약·계정 삭제용), 규칙(타이머·계정 삭제 문서 조항 포함), 함수 `updateActivitySummary`·`flushDirtyActivitySummaries`·`reconcileActivitySummaries`·`purgeDeletedFlowlogAccounts`가 운영에 나갔다. |
| 기존 사용자 요약 재계산 | **보류** (선택) | 함수는 배포됐다. Cloud Scheduler에서 `reconcileActivitySummaries` 작업을 한 번 수동 실행하면 바로 채워진다. 안 해도 기록을 저장할 때와 주 1회 작업으로 채워진다. |
| 유출된 웹 서비스 계정 키 | **완료** | 키는 이미 폐기된 상태(콘솔 "키 없음"). 웹 저장소 히스토리에서 키 파일과 export를 지우고 강제 푸시했다(2026-10-21). 다른 PC의 웹 저장소 복사본은 새로 clone해야 한다. |
| 예산 알림 | **완료** | 이미 설정되어 있었다. 최근 비용 확인 결과는 웹 저장소 문서에 둔다. |
| App Check — Android | **일부** | 서명 키 SHA-256을 Firebase에 등록하고 `org.pfkfks.flowlog`를 Play Integrity로 등록했다. 디버그 토큰 등록은 적용(enforce) 직전으로 **보류**(앱을 다시 설치하면 토큰이 바뀜). Play Console 연결은 스토어 등록 뒤. |
| App Check — 웹 | **보류** | reCAPTCHA v3 키를 만들어 비밀 키는 콘솔에, 사이트 키는 웹 `shared/appcheck.js` 두 곳에 넣어야 켜진다. 적용(enforce)은 축구판·FM24 페이지까지 덮인 뒤. 지금 웹은 App Check 토큰을 보내지 않고, 콘솔의 적용은 꺼져 있어 아무것도 막히지 않는다. |
| 비공개 테스트 12명 × 14일 | **보류** | 주인 판단으로 지금은 진행하지 않는다. 신규 개인 개발자 계정은 이것 없이는 프로덕션(정식 출시) 신청이 열리지 않는다. 시작하려면 Play Console 계정, 비공개 트랙용 AAB, 최소 앱 콘텐츠 신고(처리방침 URL, 데이터 보안, 콘텐츠 등급, 정확 알람 신고)가 필요하다. 테스터는 초대가 아니라 참여(opt-in)해야 세고, 빠지면 14일이 다시 시작된다. 돈 주고 사는 테스터와 본인 계정 여러 개는 쓰지 않는다. |

### 앱 변경 확인

| 항목 | 상태 | 내용 |
|---|---|---|
| 릴리즈 준비 작업 병합 | **완료** | 하드닝·계정 삭제·직접 추가·내보내기/가져오기·PC 앱 연동 작업을 `main`에 병합해 푸시(2026-10-21). 병합 뒤 단위 테스트 180개, 릴리즈 빌드(R8·리소스 축소) 통과. |
| 실기기 확인 | **남음** | 아래 목록을 서명이 같은 릴리즈 빌드를 덮어 설치(`adb install -r`)해서 확인한다. 계정 삭제 → 복원은 본 계정이 아니라 테스트 계정으로만. |

실기기 확인 목록:
- 정확 알람 안내가 업데이트 뒤 한 번만 뜨는지, 거절 뒤 설정에서 다시 켤 수 있는지.
- 홈 "직접 추가"(지난 활동 추가): 저장, 겹침 경고, 미래 시각 거부.
- 설정 "기록 내보내기" CSV·JSON, JSON 가져오기 미리보기에서 중복이 건너뛰어지는지.
- 런처 아이콘 길게 누르기의 타이머 시작 바로가기.
- 릴리즈 빌드에서 Google 로그인 유지, 동기화, 위젯(캐릭터 이미지·진행), 알림 소리, 잠금화면 알림 제목 숨김, App Check 초기화가 앱을 깨지 않는지.
- PC 웹 앱(`flowlog.pfkfks.org/app/`)과 왕복: 폰 시작 → PC 표시, PC 정지 → 폰 타이머 꺼짐 + 기록 하나만, PC에서 만든·완료한 할 일이 폰에 반영.
- 테스트 계정으로 계정 삭제 예약 → 재로그인 취소·복원.

### Play 정책

| 항목 | 상태 | 내용 |
|---|---|---|
| 계정 삭제 경로 (유보 14일) | **일부** | 앱 쪽 완료: 설정에서 삭제 예약 → 폰 초기화 → 로그아웃, 14일 안에 다시 로그인하면 취소·복원, 지운 기록은 서버에 내용 없는 삭제 표시로만 남김. 웹 삭제 요청 페이지(`flowlog.pfkfks.org/account/delete/`), 규칙, 인덱스, 영구 삭제 예약 함수(매일 04:00 KST)가 배포됨(2026-10-21). 남은 것: 함수용 직원 uid 환경변수(지금은 관리자만 코드로 보호되고 직원 계정은 보호되지 않음), 테스트 계정으로 실제 삭제 한 번, 데이터 보안 양식에 삭제 URL 기재. |
| 데이터 보안 양식·처리방침 정합 | **남음** | Crashlytics·Firestore 수집 항목, 관리자 열람 여부, 삭제·보존 방식을 처리방침(/privacy/)과 양식에 맞춘다. 초안은 `STORE_RELEASE_DRAFTS.md`. |
| 정확 알람 권한 | **일부** | 앱 쪽 완료: 설명 후 한 번만 묻고, 설정 창에서 다시 켤 수 있으며, 권한이 켜지면 알람을 다시 잡는다. 남은 것: Play Console에 정확 알람 용도 신고. |
| 온보딩 "Flowlog AI" 문구 | **완료** | 2026-10-20 제거. 제안 창 아이콘의 낭독 이름 "AI 메신저"는 기능 이름이라 남김. |

### 출시 전 안전·운영

| 항목 | 상태 | 내용 |
|---|---|---|
| Firestore 규칙 검증 보강 | **일부** | 저장소 규칙 사본(`docs/study-integration/firestore.proposed.rules`, 에뮬레이터 검사 43개)에 설문 응답·계정 삭제 예약·문서 크기 상한·타이머 문서를 반영했다. 남은 것: 설문 규칙의 필드 목록과 "1인 1건"을 웹 양식에 맞추기(하루 한 번 체크인과 충돌), 웹 저장소 원본 규칙에 같은 제한 반영, 사본에 남은 uid 모양 컬렉션 경로 하나의 용도 확인. 세부는 비공개 점검 보고서. |
| 로그 정리 | **완료** | 제목·uid가 찍히던 로그를 id·개수로 바꿈. 릴리즈 빌드는 R8로 debug/info/verbose 로그를 빼고, 경고 로그에도 제목을 넣지 않는다. 실제 기기 확인은 위 "실기기 확인"에 포함. |
| 서명 키 백업(PC 밖)과 Play 앱 서명 | **남음** | 키를 잃으면 같은 패키지로 업데이트를 못 올린다. Play 앱 서명을 켜면 Play의 앱 서명 키 SHA-256도 Firebase에 추가한다. |
| 스토어 자료 | **남음** | 스크린샷, 설명, 처리방침 URL, `versionCode` 27 이상과 `versionName`. 설명·처리방침 문구·데이터 보안 양식 답안 초안은 `STORE_RELEASE_DRAFTS.md`. 네임스페이스 `com.example`는 Play와 무관(applicationId는 `org.pfkfks.flowlog`). |
| 자동 백업 규칙 | **남음** (결정 필요) | 자동 백업에 무엇을 넣을지(로그인 정보 제외 여부). |

### PC 웹 앱 연동

| 항목 | 상태 | 내용 |
|---|---|---|
| 타이머 공유 | **일부** | 앱 쪽 완료: `users/{uid}/flowlog/timer` 쓰기·듣기, 나중 것이 이김. 웹 원본 규칙의 타이머 조항은 2026-10-21 배포됨. 첫 연동 빌드는 0.6.0(versionCode 27). 웹 `/app/`은 오늘 기록·열린 할 일을 실시간으로 듣고(2026-10-21), 폰이 타이머 문서를 한 번 쓰면 "0.6.0 이상 필요" 안내를 숨긴다. 남은 것: 0.6.0 설치 후 기기 왕복 확인, 폰의 정지를 웹처럼 트랜잭션으로 확인하게 하기(동시에 정지하면 기록이 두 번 생길 수 있음). |
| 웹 할 일 가져오기 | **일부** | 앱 쪽 완료: 수정 시각 기준 증분 가져오기와 병합. 남은 것: 폰이 할 일의 삭제 표시(`isDeleted`·`deletedAt`)를 읽게 해 웹 삭제를 표시 방식으로 바꾸기, 번호를 정할 때 서버 문서 유무 확인. |
