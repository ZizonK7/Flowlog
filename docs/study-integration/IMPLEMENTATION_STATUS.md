# Study–Flowlog 통합 구현 상태 (2026-09-29)

## 반영 내용
- Website: 일반 사용자 study, 관리자 전용 study/learn. 본인 통계의 실제 활동 블록에서 제목·메모·시간·분류·수업/공부/복습 관계를 편집한다. 예측·샘플·타인 활동은 편집 대상이 아니다.
- 공부 연결은 과목·날짜로 원본 기록을 선택하며 공부/복습 단계를 고르지 않는다. 새 수동 연결은 `phase=RECORD`로 원본 전체를 참조하고, 현재 제목·메모·공부/복습 완료일과 예정일을 표시한다. 연결 당시 스냅샷은 보존한다. 기존 단계별 연결과 학교 시간표의 수업 후보 연결은 호환 유지한다. 실제 시간 합계는 부모 activitySessions에서만 집계한다.
- 일과 뒤 기타 기록의 학교/이동 분류와 수업 연결 동의를 분리한다. 수업 후보는 기본 전체 선택, 선택한 연결 저장은 별도 확인한다. 제목만 수정하면 수업 승인을 기록하지 않는다.
- Android: Room v24 비파괴 마이그레이션, 관계 캐시·결정 outbox, 버전 기반 활동 업로드/원격 수정 복원, 재전송 중복 방지, 삭제 tombstone. 계정이 바뀌면 새 계정으로 이전 활동을 업로드하지 않는다.
- 앱/웹 수정 충돌은 Room에 보존하고 앱에서 양쪽 제목·분류·시각을 보여준다. 사용자가 앱 기록 유지 또는 웹 기록 사용을 선택하며, 선택 사이에 다시 변경되면 재확인을 요구한다. 수업 연결 제약 때문에 막힌 수정은 웹 상세에서 구간을 조정할 수 있다.
- 기존 AI 메신저 카드: 최근 28일의 서로 다른 3일 이상 명시적 기타→학교/이동 확인, 같은 요일 ±60분을 초기 기준으로 사용한다. 노출/분류/연결은 별도 사건이며 여러 수업을 한꺼번에 연결해도 분류 확인 횟수는 늘지 않는다. 자동 생성 출처는 근거에서 제외한다.
- 10개 상한은 UI·로컬 저장·원격 설정 로드/업로드에서 검사한다. 이번만 시작은 슬롯을 추가하지 않는다. 교체는 사용자가 대상을 고른 뒤 실행한다.

## 현재 제한과 적용 순서
- 사용자 승인 후 검증된 `firestore.proposed.rules`를 Website의 `firestore.rules`에 로컬 적용했다. 적용 파일의 SHA-256이 검증본과 일치한다. 운영에는 배포하지 않았다. 교체 전 원본 사본은 `firestore.original.rules`이다.
- 제안 규칙은 기존 활동의 관리자 읽기 범위를 유지하면서 새 수업 관계/결정 이력은 소유자만 읽게 한다. 기존 무버전 activity 쓰기는 차단한다. 구버전 클라이언트는 해당 규칙 적용 후 활동 업로드가 거부될 수 있으므로 앱 업데이트와 함께 반영해야 한다.
- 코드와 규칙을 배포하지 않았다. 새 private 경로 권한이 적용되기 전에는 새 앱/웹 조합을 운영에 배포하면 안 된다.
- 수업 연결 편집은 이번 웹 상세 화면에서 제공한다. Android는 관계를 복원하고 판단 이력을 저장/동기화하여 버튼 추천에 활용한다. Android 전용 수업 선택 화면과 로컬 관계 편집의 업로드 흐름은 아직 제공하지 않는다. StudyDao의 로컬 관계 작성 API는 UI에서 호출하지 않는다.
- 위치 수집은 별도 후속 단계다. 이번 변경은 GPS 권한이나 수집을 활성화하지 않는다.
- Android 검증은 `-PofflineValidation=true`로 실제 Firebase 설정 없이 컴파일/단위 테스트했다. 운영 로그인·실기기 Room 업그레이드·실제 다기기 동기화는 별도 확인이 필요하다.
- 원격 활동·관계·결정 복원은 아직 전체 조회 방식이다. 일반 동기화에서는 프로세스/계정별 15분 간격으로 제한하고 전체 동기화는 즉시 갱신한다. 결정 outbox 전송은 이 제한과 무관하다. 장기 이력이 커지면 서버 시각 기반 증분 동기화로 개선할 필요가 있다.

## 검증
- 2026-09-29 공부 기록 전체 연결 수정: 실제 웹 model/store 13개, Edge의 단계 선택 제거·RECORD 저장·원본 완료일 보존, 규칙 에뮬레이터 15개 검사 및 Android Kotlin 재컴파일 및 단위 테스트 98개 통과. 원본 변경 후 현재 정보 갱신과 연결 당시 스냅샷 보존, 원본 삭제 후 스냅샷 표시를 검증했다.
- Android Kotlin 컴파일과 JVM 단위 테스트 98개 통과(추천 엔진, 실제 revision 정책 및 DAO ACK/복원 로직 포함).
- 기존 study 관련 Node 테스트 35개 통과.
- 실제 웹 model/store 테스트 11개 및 normalize→timeline→click 연결 테스트 1개 통과: 분리 동의, 원본/과거 보존, phase, 시간 중첩, MOVE, 계정 전환, 버전 충돌, 중복 재시도, 실제 duration 보존, 본인 경로·예측·샘플 편집 차단.
- Playwright/Edge 모바일: 전체 기본 선택, 한 과목 제외, 분류만 저장, 이전 수업 복습 및 메모 원본 연결, 읽기 실패 저장 차단, 가로 넘침 없음.
- 실제 v23→24 SQL 실행: 기존 행 유지, 신규 소유자 복합키 확인. Room KSP 생성/컴파일 통과.
- 제안 규칙 로컬 에뮬레이터 13개 검사 통과: 소유자/타인/관리자 경계, 무버전 덮어쓰기 차단, 링크 범위, 불변 결정, 10개 상한, 사라진 부모의 연결 삭제 표식.
- 실제 웹 store의 활동·수업 연결·분류/연결 결정 원자적 커밋을 로컬 규칙 에뮬레이터에서 검증했다. 중복 재시도와 실제 duration 보존도 통과했다.
- 서버 요약·분포의 실제 함수를 실행하여 삭제 표식 제외를 검증했다. 본인 데이터 내보내기에는 원본 수업·관계·결정을 포함한다.

## 실행 방법
Flowlog에서 먼저 `node tools/study-integration/browser-test.cjs`로 실제 화면 저장 입력을 생성하고, 이어서 `node --test --test-isolation=none tools/study-integration/model-store.test.cjs`로 그 입력을 실제 store에 저장해 검증한다. 마이그레이션은 `node tools/study-integration/migration-test.cjs`.
웹 경로가 다르면 `STUDY_WEBSITE` 환경 변수를 사용한다.
권한 검증: 먼저 `node tools/study-integration/prepare-rules.cjs`, 이어서 생성된 `app/build/study-validation`에서 Firebase CLI의 `emulators:exec --only firestore --project demo-flowlog-study --config firebase.json "node rules-test.cjs"`. 운영 프로젝트를 사용하지 않는다.
